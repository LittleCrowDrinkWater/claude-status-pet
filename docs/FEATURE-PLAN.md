# 功能规划

本文记录 2026-10-13 评估过的扩展方向：每项写清楚数据从哪来、怎么做、难点在哪、还有什么没确认。标「已完成」的是已经落地的部分，其余都还只是方案。

钩子输入字段以 Claude Code 官方文档 <https://code.claude.com/docs/en/hooks.md> 为准，下文「已核实」指在该文档里确认过。

## 总览

| 序号 | 功能 | 状态 | 工作量 |
|---|---|---|---|
| 1 | 区分会话（色点、分支、标题）与持续时长 | 已完成 | 小 |
| 2 | 任务进度（3/7） | 不做 | — |
| 3 | 想法泡与说话气泡 | 已完成 | 中 |
| 4 | 状态大类与过渡动画 | 方案 | 程序中等，美术大 |
| 5 | 会话一览弹窗 | 方案 | 中 |
| 6 | 在宠物上审批 | 方案，需改钩子设计 | 中 |
| 7 | 点宠物切到会话窗口、系统通知 | 暂缓 | 中 |

建议顺序：4 的状态大类部分 → 4 的过渡动画 → 5 → 6。

## 1. 区分会话与持续时长（已完成）

### 状态文件新增字段

| 字段 | 含义 | 写入规则 |
|---|---|---|
| `title` | 会话标题 | 用 `/rename` 设过名字时取这个名字（`UserPromptSubmit` 和 `SessionStart` 输入里的 `session_title`，已核实）；否则取第一次提问的第一行，合并空白，最多 40 个字符。斜杠命令和以 `<` 开头的注入内容不当标题。一旦有值就沿用 |
| `branch` | Git 分支 | 提问时，或会话还没有状态文件时，从 `cwd` 往上找 `.git`；支持工作树（`.git` 是文件、指向真正的 git 目录）；游离 HEAD 时取提交号前 7 位。其余事件沿用旧值 |
| `turn_started` | 本轮开始时间（Unix 毫秒） | 提问事件写当前时间，其余事件沿用 |
| `state_since` | 进入当前状态大类的时间（Unix 毫秒） | 状态大类变化时写当前时间，否则沿用 |

状态大类：思考、读文件、改代码、搜索、跑命令、派子代理都算「干活」，其余状态各自成一类。一轮里工具会频繁切换，如果按单个状态计时，计时会不停清零。

逻辑在 `pet-app/src-tauri/src/session_meta.rs`。`write-status` 每次只读一次旧状态文件，同时用来沿用这些字段和复用 Claude 进程。

### 显示

- 标签前加一个色点，颜色由会话 ID 算出，同一会话始终同色。
- 同一目录下有多个会话时，标签后缀优先用分支名，分支也相同才用会话 ID 前 4 位。
- 状态标签后面显示时长，如「RUNNING · 12m」：干活中从本轮提问算起，等审批从进入等审批算起，满 1 分钟才显示。时长每分钟变化一次时只改标签，不重新播放气泡动画，也不重新随机挑图。时长原本放在气泡末尾，第 3 节加了想法泡后，较长的想法会把它挤出两行的显示范围，所以挪到标签上。
- 鼠标悬停标签显示「目录 [分支] / 标题 / 状态 · 时长」。
- 右键 → Sessions：每个会话两行，第一行是色点加名称，第二行是「状态 时长 · 标题」。时长和状态放在前面，因为窗口只有 200px 宽，后面的内容会被截断。

只在汇总模式（`run --all`）显示，单会话模式不处理。

## 2. 任务进度（不做）

**原想法**：Claude 更新待办清单时，从 `PreToolUse` 的 `tool_input` 里数出已完成数和总数，在气泡里显示「3/7 改代码中」。

**不做的原因**：
- 官方工具文档（<https://code.claude.com/docs/en/tools-reference.md> 的 Task tool availability 一节，适用于 Claude Code v2.1.268 及以后）写明，待办工具 `TaskCreate`、`TaskGet`、`TaskList`、`TaskUpdate`、`TodoWrite` 只在 Opus 4.7、Sonnet 4.6、Haiku 4.5 及更早的模型上默认提供。更新的模型默认不提供，理由是新模型不靠清单也能跟住多步任务，而且工具定义会占用上下文。
- 本机 13 个项目、87 份会话记录里没有一次待办工具调用，平时用的 Opus 5.5 没有这些工具。
- 要用就得设置 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` 或用 `--allowedTools TaskCreate` 启动。为了宠物显示进度去改变 Claude 的工作方式，不值得。

**替代思路（未排期）**：`Stop` 输入里有 `background_tasks`，可以显示「后台 2 个任务」这类信息，不依赖待办工具。

## 3. 想法泡与说话气泡（已完成）

### 数据来源

| 气泡 | 字段 | 来源 | 规则 |
|---|---|---|---|
| 想法泡（干活中） | `thought` | `PreToolUse` 输入的 `transcript_path` 和 `tool_use_id`（已核实） | 从会话记录末尾往回读，先读 64 KB，找不到就加倍，最多 256 KB。找到这次工具调用所在的那一行后，往前找同一条消息（`message.id` 相同）里的文字，遇到上一条用户记录（提问或工具结果）就停。取第一个非空的段落，去掉 Markdown 记号，最多 120 个字符 |
| 对话框（回合结束） | `reply` | `Stop` 输入的 `last_assistant_message`（已核实） | 跳过标题、表格、代码块和分隔线，取第一句（遇到句号、问号、叹号就截断；英文句点后面要跟空格才算，避免把 `app.js` 切开），去掉 Markdown 记号，最多 120 个字符 |

两个字段都不沿用：每个事件只写自己算出的值，其余为 null。逻辑在 `pet-app/src-tauri/src/speech.rs`。

### 实测数据（2026-10-13，本机会话记录）

- 用 Opus 5 系列跑出的 11311 次工具调用里，2832 次（约 25%）前面有文字，长度中位数 56 个字符，前 90% 不超过 136。其余约 75% 的工具调用没有文字，这时想法泡显示原来的工具信息。
- 1294 条回合结束的回复，长度中位数 1128 个字符，前 90% 不超过 2180，最长 7272；93% 以普通段落开头。
- 记录文件中位数约 1.1 MB，最大 42 MB，所以只读末尾。
- 记录里，调工具前写的文字单独占一行，紧挨在工具调用那一行前面，两行的 `message.id` 相同。并行调用多个工具时，每个工具单独占一行，共用前面那段文字。
- 模型的思考过程在记录里是加密的，取不到。

### 时机

官方文档说记录文件是异步写入的，钩子触发时可能还没写入最新的消息。本会话实测：工具执行时，前面的文字已经写进去了。但这只是一次观察，所以设计成找不到就不显示，不等待、不重试。

### 显示

- 干活的状态（思考、读文件、改代码、搜索、跑命令、派子代理）用云朵形的想法泡：圆角更大，下面是两个小圆点。其余状态用原来带尾巴的对话框。
- 有 `thought` 就显示它，没有就显示工具信息；空闲时有 `reply` 就显示它，30 秒后收起。
- 气泡最多两行，鼠标悬停显示全文。
- 右键 → Settings → Speech 可以关掉，关掉后只显示工具信息。宠物一直浮在桌面上，开会共享屏幕时会露出对话内容。
- 汇总模式只显示当前选中的那个会话的内容。

### 已知不足

- 只支持 Claude Code：Copilot 和 VS Code 的钩子输入里没有对应字段。
- 调工具那一刻能不能读到前面那段话，只实测过一次。如果实际使用中想法泡几乎不出现，说明多数时候记录文件还没写入，到时再考虑在工具执行完后补读一次。

### 从宠物到会话（基本不可做）

没有接口可以往运行中的 Claude 终端注入输入。模拟键盘可以做到，但很脆弱，不采用。唯一可行的交互是审批，见第 6 节。

### 未做：Claude 主动说话

新增 `claude-status-pet say "..."` 子命令或 MCP 工具，在 CLAUDE.md 里约定什么时候用。是否调用、多久调用一次都不可控，先不做。

## 4. 状态大类与过渡动画

**目标**：例如从空闲到干活时，桌子滑进来、宠物坐下、打开电脑，而不是淡入淡出。

**现状**：换图时先淡出 150ms，同时整体播放一段出现动画；每个状态各有一套循环晃动（CSS 关键帧），状态之间没有过渡。

### 程序部分

1. **只在状态大类之间播放过渡**：大类就是第 1 节的分组（空闲、干活、等审批、出错……）。读、改、跑命令一秒内可能切好几次，大类内部只换桌上的小道具，比如屏幕上的图标，不重播过渡。这一步本身也能减少汇总模式下的频繁换图，可以先单独做。
2. **打断处理**：过渡播到一半就进入新状态时，要么播完再切，要么从当前进度倒放（Web Animations API 支持倒放）。另外设最短停留时间。
3. **角色包格式**：`character.json` 增加可选的 `transitions` 字段，例如 `"idle->working": ["sit-1.png", "sit-2.png"]`。没写这个字段的角色仍然淡入淡出，现有角色不受影响。

### 美术部分（主要成本）

Ferris 的 SVG 来自一套独立插画，没有「坐下」「打开电脑」这类过渡画面。可选路线：

| 路线 | 优点 | 缺点 |
|---|---|---|
| 逐帧序列（PNG 或 GIF 帧） | 最直观，格式现成 | 每个过渡都要画一组帧，还要和循环动画首尾衔接 |
| 分层 SVG（身体、桌子、电脑分开，用程序控制位移和旋转） | 桌子滑入、电脑开合可以用程序做 | 「坐下」这类身体动作很难做自然 |
| Rive 或 Lottie | Rive 自带「状态加过渡」的模型，和需求最吻合；运行库可以打包进前端 | 要用它们的编辑器制作角色 |

建议先用分层 SVG 做一个简化原型：桌子和电脑做位移动画，宠物只换「站」「坐」两个姿势，确认效果后再决定是否投入正式美术。

## 5. 会话一览弹窗

**目标**：鼠标悬停宠物时显示所有会话的状态表。

**难点**：宠物窗口只有 200×240，放不下表格；窗口从左上角往外扩，宠物又停在右下角，直接放大会超出屏幕。

**做法**：另开一个无边框的小窗口（Tauri 支持多窗口），悬停时显示在宠物左上方，内容复用第 1 节的字段。现在悬停标签的提示文字和右键 Sessions 菜单可以先顶着用。

## 6. 在宠物上审批

**依据（已核实）**：`PermissionRequest` 钩子在弹出权限确认时触发，输入包含 `tool_name`、`tool_input`。返回以下内容即可放行或拒绝：

```json
{ "hookSpecificOutput": { "hookEventName": "PermissionRequest", "decision": { "behavior": "allow" } } }
```

拒绝时把 `behavior` 改成 `"deny"`。必须是 command 类型的钩子。

**冲突**：这个钩子必须同步等待宠物的回复，和现在「钩子绝不阻塞」的原则冲突。需要单独设计：
- 宠物不在运行，或在超时时间内没有响应，就不返回决定，交回终端照常弹出审批；
- 钩子进程和宠物之间的通信方式（文件、命名管道或本地端口）；
- command 类型钩子的默认超时时间文档没有写，需要实测。

## 7. 暂缓

- **点宠物切到会话窗口**：状态文件里已有 `claude_pid`，可以顺着父进程找到终端窗口切到前台。限制是 Windows Terminal 多标签时切不到具体标签页。
- **系统通知或提示音**：进入等审批，或长任务结束时弹 Windows 通知，要用 Tauri 的通知插件。
- **非 Windows 的会话存活判断**：Linux 和 macOS 上用 `/proc` 或 `ps` 找 Claude 进程。

## 已核实的钩子字段

来源：<https://code.claude.com/docs/en/hooks.md>

- 所有事件共有：`session_id`、`transcript_path`、`cwd`、`hook_event_name`；多数事件有 `permission_mode`；用户首次提问后有 `prompt_id`。
- `UserPromptSubmit`：`prompt`（提问原文，折叠的粘贴内容会展开）；设过自定义标题时有 `session_title`。除了用户输入，定时任务（含 `/loop` 每次迭代）、后台子代理的汇报、其他会话发来的消息也会触发它，所以「本轮开始时间」偶尔会被这些事件重置。
- `Stop`：`stop_hook_active`、`last_assistant_message`、`background_tasks`、`session_crons`。
- `PermissionRequest`：见第 6 节。
- `PreToolUse`：`tool_name`、`tool_input`、`tool_use_id`。
- `transcript_path`：记录文件是异步写入的，钩子触发时可能还没写入本轮最新的消息；需要回合结束时的最后一句话，应该用 `Stop` 的 `last_assistant_message`。
- 异步钩子（`"async": true`）收到的输入和同步钩子一样，Claude Code 不等它结束。
- 文档没有写：斜杠命令是否触发 `UserPromptSubmit`。
